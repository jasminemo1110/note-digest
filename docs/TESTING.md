# 验证流程

## 自动检查

运行 npm test 和 npm run build。测试须覆盖原文变更、重复匹配、过长/畸形 AI 响应、Markdown 转义和插入。

## 真实 Obsidian（发布前必做）

使用 examples/test-vault 的副本作为仓库，复制构建三件套到 .obsidian/plugins/note-digest，启用插件。

- 阅读视图选中普通英文 → Digest → 右侧显示中文；不点击保存则文件完全不变。
- 编辑模式选区命令可用，多行/列表/引用/链接内容不破坏 Markdown。
- 配置 SecretStorage，主动请求 DeepSeek；检查空密钥、鉴权失败、网络中断。
- 译文添加到下方与括号；再次插入不能重复写入。
- 请求期间编辑、切换文章、再次发请求，旧响应不能覆盖新状态或错误写入。
- 重复句子或富文本无法唯一定位时安全提示。
- 插件卸载/重载后不残留按钮或重复监听。

后续 P2/P3 完成后补充：三种保存目标、重试去重、来源改名/移动、高亮准确性、长文完整覆盖、摘要定位、全文停止恢复和双语导出。

## 当前限制

自动测试和构建通过不代表真实 Obsidian 或模型质量验证。未执行项目必须在路线图保持未勾选。

## 0.2.0 收藏和高亮验收

真实宿主待验证（界面控制服务仍启动失败）：

1. 用专用收藏测试文章，词语 → 语境解释 → 两者都保存。确认文末和独立学习笔记都有音标、含义、全部用法、例句和表达判断，且原词高亮。
2. 再次点击保存，两处均不重复；在学习笔记加入手工备注后重试，备注保留。
3. 金句翻译后分别测试仅文末、仅独立笔记，确认没有写入未选择的目标。
4. 阅读视图重开/插件重新加载，收藏高亮仍在；同词不同段落不误标。
5. “取消收藏高亮”使高亮消失，Markdown 笔记保留；再次收藏不会重复追加。
6. 插件运行时改名或移动原文，通过侧栏定位到新来源。修改原段落后不误标旧位置。
7. 修改密钥名称再重载，收藏仍存在；此步骤只由用户在 SecretStorage 设置中操作，不输出密钥。
